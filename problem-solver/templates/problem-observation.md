# Detailed Problem Observation Record

Use this before writing a generalized problem statement. Describe the observable situation in the domain's own operational language.

## 1. Setting
- Where does the problem occur?
- Which actors, texts, tools, cases or processes are involved?
- Under what conditions?
- What is the normal workflow before the failure occurs?

## 2. Concrete observation
- What exactly was observed?
- Provide examples, excerpts, records, calculations or output differences.
- What happened before / during / after?
- Frequency and magnitude, if known:
- What is directly observed versus inferred?

## 3. Failure morphology
Mark and describe only those observed:
- missing information;
- conflicting instructions;
- inconsistent terminology;
- untraceable attribution;
- incomplete procedure;
- hidden preconditions;
- rule interaction / precedence ambiguity;
- version or edition drift;
- manual calculation inconsistency;
- incorrect output;
- retrospective reinterpretation;
- low reproducibility;
- no negative examples;
- missing outcome records;
- weak external validation;
- source contamination / copied material;
- other (specify).
